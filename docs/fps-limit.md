# Лимит FPS: 30 / 60 / без лимита (меню «Настройки → Экран»)

Статус: **сделано, проверено на десктопной сборке** (2026-11-08). На консоли не проверялось.

## Как пользоваться

* В игре: «Настройки → Экран → ОГРАНИЧЕНИЕ FPS ◀ 30 / 60 / ОТКЛ. ▶». Выбор сразу применяется и записывается
  в `sdretail.toml` рядом с NRO (строка `sdretail_fps_limit = …`, остальное содержимое файла сохраняется).
* Без меню: `sdretail_fps_limit = 30 | 60 | 0` в `sdretail.toml`.
* Строка меню появляется только на данных, пропатченных `port/tools/apply_branding.py` (по умолчанию включено,
  `--no-fps-menu` — отключить). Без патча лимит работает из toml.
* Контроль без экрана: `sdretail_fps_log = true` — раз в 5 с в лог пишется фактическая частота флипов.

## Как устроено

| Часть | Где | Что делает |
|---|---|---|
| Лимит | хук `sub_82BBC580` (очередь флипа D3D) | интервал презентации в битах 8–11 `r3`: игра ставит 2 (30 fps при vblank 60 Гц); 60 → 1, «откл.» → 0, 30 → как у игры |
| Строка меню | `port/tools/fps_menu_patch.py` → ролик `Options_Display` (`UI.big`, `0xEBCA65F0`) | в конец скрипта кадра дописан AS2: строка с id `OPTIONS_FPS_LIMITER`, подписи `30`, `60`, `$COMMON_OFF_UPPERCASE`, функция `SDNX_SetFpsLimit(i)` |
| Нажатия влево/вправо | хук `sub_827ECC70` (`handleMessage` экрана) | FSCommand `OPTIONS_FPS_LIMITER` = хэш `0x3EAA29C9`; значение — `sub_827AD340(msg)`; cvar + запись в toml |
| Текущее значение при открытии | хук `sub_827C9358` (заполнение экрана) | после `OptionList_SetValues` игры — `Invoke("SDNX_SetFpsLimit", i)` (ролик `*(*(screen+76)+312)`, Invoke = vtable +92, число — `sub_8270E9B0`) |

Код: [nx/sdretail/src/sdnx_fps_limit.cpp](../nx/sdretail/src/sdnx_fps_limit.cpp). Подпись «ОГРАНИЧЕНИЕ FPS» —
готовая строка PC-версии (`OPTIONS_FPS_LIMITER`, есть во всех 7 языках): ключ текста = `qStringHashUpper32` имени.

Грабля: слоты списка в ролике закреплены за типами PC-раскладки (`slot2` — разрешение, `slot3/4` — вкл/выкл,
`slot5` — спиннер). Третья строка попадает в `slot2`, поэтому она оформлена как «разрешение» (стрелки + список
подписей); спиннер там показывал `undefined`.

## Проверка (десктоп, данные `port/testroot`)

| Прогон | Результат |
|---|---|
| `sdretail_fps_limit = 30` | 30.0 флипов/с, интервал 2 (как у игры) |
| `= 60` | 60.0 флипов/с, интервал 1 |
| `= 0` (+ `--vsync false`) | 730–800 флипов/с, интервал 0 |
| меню: вход в «Экран», вправо ×N (`port/tools/fps_menu_test.ps1`, ввод с клавиатуры) | «Display menu opened … accepted by the movie», значения 30 → 60 → откл. → 30 применяются сразу, toml обновляется, `[log.levels]` сохраняется |

Оговорки: на экране 60 Гц «без лимита» выше 60 fps даёт разрывы изображения. На Switch-SDK swapchain может
работать в IMMEDIATE, поэтому 60 Гц сверху не ограничивают.
